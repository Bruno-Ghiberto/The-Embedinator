- **Severity**: MAJOR
- **Layer**: Backend
- **Discovered**: 2026-06-26T20:05:00Z in Phase 3 (P3-S4)
- **Phase scenario**: P3-S4
- **BLOCKER-PATCHED**: no

## Steps to Reproduce
1. In a session where session continuity holds (a shared LangGraph thread across turns — see Reachability note below), compare `agent_aggregate_answers_merged.num_citations` per turn — each turn's OWN deduped citation count (organic session c5ffb174: T1=5, T2=10, T3=10) — against `agent_format_response_formatted.num_citations` for the SAME turn — the accumulated conversation-STATE total (T1=20, T2=70, T3=170).
2. Cross-reference `query_traces.chunks_retrieved_json` byte length across the 3 turns: 14,408 → 49,544 → 120,258 bytes (~8.3x growth by T3), confirmed via DB export.
3. Compare against what the CLIENT actually receives: the streamed `citation` NDJSON event, and the "sources" panel count in the UI.

## Expected
The backend's internal `ConversationState.citations` accumulator either resets between turns or is deduplicated at every consumption site, so the trace-persistence column (`chunks_retrieved_json`) does not balloon across an open-ended conversation.

## Actual
`ConversationState.citations` accumulates unbounded across turns via the `operator.add` reducer, never reset within a shared thread (raw entries 20→70→170, ~120KB by turn 3, DB-verified).

The accumulated list REACHES THE USER-VISIBLE ANSWER BODY whenever a turn terminates at `fallback_response` rather than `collect_answer` — i.e. on the zero-retrieved-chunks path (embedder/dimension mismatch per BUG-098, Qdrant unavailable, an empty/misconfigured collection, or a wall-clock deadline hit before any successful search). On that path the answer text is corrupted with a raw, un-deduped `**References:**` block (50 entries observed at P5-S4) plus a duplicate `*Note: Confidence score is …*` line that the frontend already renders via ConfidenceMeter. On the normal streaming path (`collect_answer`), the re-emit is correctly skipped and the accumulation stays confined to backend state plus the `chunks_retrieved_json` trace column.

Secondary user-visible effect on all paths: the "sources" panel count grows and stale prior-turn sources persist into later turns (5→10→10, bounded to the count of unique passages retrieved so far, not unbounded).

> **Retraction notice**: an earlier revision of this record asserted the accumulated text is "CONFINED to backend state … NOT user-visible in the assistant's answer text." That claim was **RETRACTED on 2026-07-10** and is false on the zero-retrieval path; it was the sole justification for the original MINOR/Observability classification, which is why this record is now MAJOR/Backend. Full retraction reasoning and blast-radius trace in Notes.

## Root-cause hypothesis
HIGH confidence, code-confirmed, 3-part: (a) `backend/agent/state.py:54` — `citations: Annotated[list[Citation], operator.add]` on `ConversationState`; the LangGraph reducer concatenates every node write onto the checkpointed session state, and nothing resets it between `HumanMessage` turns within the same `thread_id`. (b) `backend/agent/nodes.py:804` + `814-825` (`format_response`) computes inline `[N]` markers + a "**References:**" section from the FULL accumulated `state.get("citations", [])` with no dedup. Whether that text reaches the client is decided by the `not has_streamed_response` guard at `backend/api/chat.py:239-242`. `has_streamed_response` is set True ONLY by the `collect_answer` node (`chat.py:226-231`), so on a normal turn the re-emit is correctly skipped. But `collect_answer` and `fallback_response` are the ONLY terminal nodes, and `fallback_response` does not stream — `should_continue_loop` (`research_edges.py:19-114`) routes to it only when ZERO chunks were retrieved (the `if state.get("retrieved_chunks")` gate at `:72`, `:96` and the deadline branch; design comment at `:44-52`). On that path the guard is False and the bloated, un-deduped reference text IS emitted into the answer body, along with the trailing confidence note (`nodes.py:836-838`) that rides the same emit path. A second non-streamed route exists at `aggregate_answers` (`nodes.py:~386-397`), which sets `final_response` directly with `citations=[]` — reproducing the confidence-note leak without the References block, since `format_response`'s `if citations:` gate (`nodes.py:814`) skips it. (This supersedes this record's original "the bloated reference text never reaches the browser" claim, retracted 2026-07-10 — see Notes.) (c) `backend/api/chat.py:303-305` — `chunks_retrieved_json` (the trace-persistence column) serializes the same raw accumulated list with no dedup; this is a real, DB-verified defect, confined to the observability/trace surface. By contrast, the streamed `citation` NDJSON event IS deduped by `passage_id` (`chat.py:245-256`, comment "# BUG-017: Send() fan-out produces N copies") — so the user-facing citation count the client actually renders is the TRUE unique count per turn (5→10→10, plateauing at 10, never ballooning to 170).
