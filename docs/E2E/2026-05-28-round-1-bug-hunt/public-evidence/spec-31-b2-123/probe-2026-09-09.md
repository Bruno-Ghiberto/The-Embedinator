reproduces the 2026-09-02 result on the images that carry ALL of units 1–4.

## Deviations and reading notes (recorded so the numbers are not over-read)

1. **The literal sentence `The response stalled: no data for 120s.` did NOT render**, and the
   poller's `stalled_paragraph_present` signal stayed `false` for the whole run. This is the
   shipped behaviour, not a miss: `useStreamChat.ts:59` writes `content: msg.content || message`,
   so the stall sentence replaces the bubble text ONLY when nothing had streamed yet. Here 337
   characters of partial answer had already arrived, so the partial text is kept and the terminal
   state is carried by `isError` / `errorCode = "STREAM_STALLED"` / `isStreaming = false`, the
   destructive bubble styling and the `Retry` control. All of those were read directly off the
   React fiber at 13:35:14.499Z and are in `probe-2026-09-09-page-poller.json` under `readings`.
   The 2026-09-02 run saw the sentence because that stream was killed before any token arrived.
2. **The kill landed at +22.4 s after submit**, just outside the runbook's 10–20 s window: the
   probe was held back to clear a host-side test run. This does not touch the measurement, which is
   anchored on `t_last_frame`, not on the submit.
3. **`http_status=000000` lines in the host poll** are the curl loop's own artifact: on a `-m 2`
   timeout curl prints `000` via `-w` and the `|| echo 000` fallback appends a second `000`. Read
   them as "timed out" (the proxy hanging past 2 s) as opposed to the `500` lines (the proxy
   fast-failing). Neither is a success; there is no 200 between 13:32:14.576 and 13:35:38.644.
4. **`composer_disabled` was `false` during the outage until the watchdog fired.** The textarea is
   left enabled while a stream is in flight (only the Send button is gated), and the backend-down
   state disables it once streaming ends. Expected, recorded for completeness.
5. The first `readings` entry in the JSON contains a stale-fiber read of the post-retry bubble
   (`isStreaming: true`); the entry immediately after it is the correction, taken from
   `fiber.alternate` (React's committed tree). The corrected values are the ones used above.
