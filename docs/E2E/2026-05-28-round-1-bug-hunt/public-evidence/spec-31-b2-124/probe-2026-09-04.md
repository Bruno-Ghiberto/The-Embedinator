# BUG-124 live probe — 2026-09-04 (spec-31 Batch 2 unit 3, task 2.6)

**Question**: after the backend comes back from a ~3-minute outage, how long does the chat page
stay locked on "Connecting to backend..." with the composer disabled?
**Record**: 31–60 s (P7-S1, 2026-07-28). **Measured 2026-09-02 on the pre-fix image**: banner
recovered **197 s after** the container reported healthy (`../spec-31-b2-gc2/browser-probe-2026-09-02.md`).
**Fix under test**: `frontend/components/BackendStatusProvider.tsx` — an explicit SWR `onErrorRetry`
that re-probes at `POLL_INTERVAL_MS` (5 s) instead of SWR's default exponential backoff.

## Setup

- Stack: the four Docker services from `docker-compose.yml` + `docker-compose.gpu-nvidia.yml`.
  Frontend container recreated at 12:54:37Z from image `117b66e9…` built at 09:32 local from the
  fix commit (production bytes identical to the squashed work-unit commit); healthy at 12:54:53Z.
- Browser: Playwright MCP on `http://localhost:3000/chat` (through the Next proxy — never `:8000`).
  Page loaded at 12:55:02Z and settled on `Backend connected` (banner) before the outage.
- Docker half: `probe-124-docker.sh 190` — `docker stop embedinator-backend`, hold 190 s,
  `docker start`, then stamp the first `healthy` from `docker inspect` (0.5 s resolution).
- Host half: `curl` loop against `http://localhost:3000/api/health` every 1 s, stamping the first 200.
- Page half: a 100 ms poller installed with `page.evaluate` at 12:57:42Z (mid-outage; banner
  `Connecting to backend...`, composer `[disabled]`) that stamps the first `Backend connected`
  and the first enabled composer (`probe-2026-09-04-page-poller.json`).

## Result

| Lag of the UI recovery, measured from… | 2026-09-02 (pre-fix image) | 2026-09-04 (fixed image) |
|---|---|---|
| first successful `/api/health` through the proxy | n/a (not stamped) | **+1.5 s** |
| `docker start` issued | +222 s (13:05:26 → 13:09:08) | **+6.4 s** |
| container health = `healthy` | **+197 s** | **−4.0 s** (the page saw the backend before Docker's 10 s-interval healthcheck did) |

The UI followed the backend within ONE 5 s poll interval of the first reachable probe. The
behaviour the record asked for ("recovers within roughly one configured poll interval (~5s) and
the user can type") holds on the live stack through the proxy. A manual `docker stop` is not
auto-restarted (`restart: unless-stopped`); the script starts the container by hand.
